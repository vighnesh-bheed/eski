# Text analysis contracts

This optional Lean 4.35.0 project covers the text-analysis leaf `src/text`: the byte classes, the document tokenizer, the Unicode lower-casing table and the fold that uses it, the stop-word tables and the analysis pipeline that numbers positions and adds stem terms, together with the English stemmer `src/stem_english` as the pipeline calls it. It uses only Lean core and adds no server dependency. The theorems are about Lean definitions that transcribe the Odin procedures; the bridge supplies finite evidence that the actual packages agree with them, and makes no claim that the Odin executable is formally verified.

Run from the repository root:

```sh
python3 -I proofs/text/verify.py --lean-bin /absolute/path/to/lean/bin --odin /absolute/path/to/odin --output /absolute/path/to/results
```

The lower-casing check reads the Unicode 17.0.0 `UnicodeData.txt` and `SpecialCasing.txt`, which the repository carries unmodified with the Unicode License v3 in [third_party/unicode/ucd-17.0.0](../../third_party/unicode/ucd-17.0.0); `--ucd` names another directory holding the same files, and the verifier refuses files whose SHA-256 differs from the pinned values in [verify.py](verify.py). The files are data only and nothing in them is executed. `LEAN_BIN_DIR` supplies the Lean directory when `--lean-bin` is omitted, and the Odin compiler is taken from `--odin`, then `ODIN`, then `PATH`, then `~/odin/current/odin`. The default output directory is `proofs/text/.build`. The verifier removes a previous success receipt, checks the source drift gate, builds the Lean library and `text_model` executable and the Odin harness with `-vet -strict-style` under the repository's `.build/proofs/compiler.lock`, runs the shared [kernel audit](../README.md#audit-coverage) with `Texts.lean` as the printed manifest, generates the deterministic corpus, runs both executables on it and compares every row with independent Python expectations and with each other. It uses nice 10, one allowed CPU and one Lean thread and starts no server. The [aggregate runner](../README.md#run-the-proof-projects) runs it as `--project text`.

`Texts/Classes.lean` restates the byte table as predicates and proves the tokenizer's rules over all 256 bytes: only space, tab and the ASCII punctuation other than `_` and `\` separate, every control byte except NUL and tab is removed, NUL ends the value, and the classes partition the bytes the tokenizer distinguishes. `Texts/Tokenize.lean` transcribes the tokenizer and proves `tokenize_spec`, that its token texts are exactly the non-empty pieces of a simple specification that splits at separators, drops removed bytes, keeps the byte after a backslash unless it is a control byte, and stops at NUL; `tokenize_clean` proves every token is non-empty and free of control bytes. Each token's tail starts at its start plus its text length, as in the Odin slow path. `Texts/Fold.lean` proves the UTF-8 encoder and decoder inverse on scalar values, that folding ASCII text lower-cases it byte for byte and stops at NUL, and that the fold of an ASCII prefix followed by encoded scalar values is the lower-cased prefix followed by the encoded lower-case sequence of those values; `trie_truncates_emoji` and `trie_limit` record that the trie form keeps only the low 16 bits of a code point and refuses terms over 255 units. `Texts/Stop.lean` proves the table holds exactly the sorted, de-duplicated folded words, that the length and first-byte filters never reject a member, and that a positive answer always names a member, so there are no false positives; the default list's 33 words fill a 128-slot table and all are found. `Texts/Analyze.lean` proves the pipeline's specification: kept words receive consecutive positions from the field base plus one, the returned last position is the base plus the kept count, a stop word is skipped only when its folded form is non-empty, and a `+` stem term appears exactly when a stemmer is present, the folded term has at least the minimum length (4 by default) and the stem differs, at the word's own position and offsets. `overlong_nul_empty` shows that the token `C0 80` folds to the empty term, which `empty_kept` keeps with a position even when the stop list contains the empty word.

The bridge [bridge.odin](bridge.odin) imports `src/text` and `src/stem_english` directly and replays the same case file as [Main.lean](Main.lean). The independent Python model in [verify.py](verify.py) restates the byte rules, tokenizes with its own state machine, lowers with its own parse of `UnicodeData.txt` field 13 and the unconditional entries of `SpecialCasing.txt` (it never uses `unicodedata`), checks stop words by set membership and takes Porter2 stems from the vendored Snowball lists `src/stem_english/testdata/voc.txt` and `output.txt`. The Lean executable reads the same two Unicode files. Analysis rows run with no stemmer, with the real English stemmer over vocabulary words, and with a fixed stand-in stemmer that strips `ing` or `s` and refuses short output buffers so the retry loop runs.

The deterministic seed `0x7E575EED` gives 28,228 rows: 256 byte-class rows, 3,029 tokenizer rows, 15,222 folding rows (4,506 folds including every mapped code point, 8,192 table rows covering all 2^21 code points with the 1,488 mapped code points and 103 unconditional special casings, 1,514 encoder rows and 1,010 trie-form rows), 2,349 stop-word rows over default, empty and custom lists with duplicates, case variants, empty words and words over 63 bytes, and 7,372 analysis rows (4,913 stemmer checks and 2,459 analyses). Every row kind and column is mutated as a negative control, together with empty, truncated and extra output and 14 semantic mutants: escaped control bytes kept, NUL treated as a separator, a fold that ignores the tail, simple casing only in the fold and in the table, conditional casing applied, supplementary code points kept in the trie form, stop words left in input order, query drops for non-plain terms and despite the no-stop-words flag, short words stemmed, stem terms advancing the position, stop words taking positions and empty terms dropped. All 46 controls must be rejected. [source-sha256.json](source-sha256.json) pins the eight modelled `src/text` sources, the stemmer and its two vocabulary files; a change stops verification for review and reconciliation. Hashes detect drift; they do not establish refinement.

The receipt records the named theorem manifest with each theorem's axioms, the kernel inventory, per-area theorem names and comparison counts, source, Unicode, trace, result and executable hashes and the compiler versions. The areas are `classes`, `tokenizer`, `folding`, `stopwords` and `analysis`, and each has comparison rows. All 74 named theorems and all 253 kernel-checked theorems depend only on `propext`, `Classical.choice` and `Quot.sound`; there is no `sorry`, no project axiom and no native evaluation. The lower-casing table is checked against the Unicode data by comparison over every code point, not by proof. Porter2 is compared only. Position wrap-around at the u32 ceiling, allocation failure, the language table and the query-side term handling beyond `query_drops_term` are outside the proofs. `THIRD_PARTY_NOTICES.md` has no entry for the Unicode data from which `lower_table.odin` is generated. No performance claim is made here.
