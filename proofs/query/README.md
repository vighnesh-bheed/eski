# Query parser contracts

This optional Lean 4.35.0 project covers a fragment of the query parser `src/ftquery`: the lexer for words, stop words, prefix, suffix and infix patterns, `|`, `-`, `~`, parentheses and ignored commas, the binding powers of dialects 1 and 2, the node constructors that flatten unions and intersections, and the EXPLAIN printer for the resulting trees. It uses only Lean core and adds no server dependency. The theorems are about Lean definitions that transcribe the Odin procedures; the bridge supplies finite evidence that the actual package agrees with them, and its recorded rows compare the model with the reference engine's output, recorded black-box in the package's test data. It makes no claim that the Odin executable is formally verified.

Run from the repository root:

```sh
python3 -I proofs/query/verify.py --lean-bin /absolute/path/to/lean/bin --odin /absolute/path/to/odin --output /absolute/path/to/results
```

`LEAN_BIN_DIR` supplies the Lean directory when `--lean-bin` is omitted, and the Odin compiler is taken from `--odin`, then `ODIN`, then `PATH`, then `~/odin/current/odin`. The default output directory is `proofs/query/.build`. The verifier removes a previous success receipt, checks the source drift gate, builds the Lean library and `query_model` executable and the Odin harness with `-vet -strict-style` under the repository's `.build/proofs/compiler.lock`, runs the shared [kernel audit](../README.md#audit-coverage) with `Queries.lean` as the printed manifest, generates the deterministic corpus, runs both executables on it and compares every row with independent Python expectations and with each other. It uses nice 10, one allowed CPU and one Lean thread and starts no server. The [aggregate runner](../README.md#run-the-proof-projects) runs it as `--project query`.

`Queries/Tree.lean` gives each node a set denotation and proves that `make_and` and `make_or` denote conjunction and disjunction of their non-null operands in every dialect, including the left append and the dialect 2 right merge, which places the left operand after the right one's children, that a null operand is the identity, that `make_not` denotes complement and collapses a double negation, and that the constructors never return null from non-null operands. `mkAnd_right_nested_one` and `mkAnd_right_merge_two` state the dialect difference directly. `Queries/Lexer.lean` proves that every token stream ends with exactly one closing token, an end or an unsupported marker, and that every other token is a real token starting at or after the scan position; `lexStep_emit` shows each emitted token advances the scan by at least one byte. `Queries/Parser.lean` proves the binding-power facts that decide precedence: in dialect 2 `|` binds most weakly and patterns bind more tightly than juxtaposition, while in dialect 1 `|` binds most tightly and a negation extends over the following terms. `Queries/Facts.lean` evaluates the model on 23 queries, among them `-x y`, which is `NOT{x y}` in dialect 1 and `x` negated and intersected with `y` in dialect 2, `x (y z)`, which nests in dialect 1 and merges as `y z x` in dialect 2, and `*xy* *z q*`, whose dialect 2 order follows from the pattern binding power, together with the error offsets and near texts of unbalanced groups and a dangling `|`.

The bridge [bridge.odin](bridge.odin) imports `src/ftquery` and runs the real `parse` with a one-text-field schema, the default stop words and verbatim terms, then `explain`, and the real lexer for lexer rows; it replays the same case file as [Main.lean](Main.lean). The independent Python model in [verify.py](verify.py) is a separate Pratt parser over the same binding-power tables with its own lexer and printer. Reference rows take the recorded cases from `src/ftquery/probe_cases_test.odin` and `recorded_cases_test.odin` whose query lies in the fragment, uses verbatim terms and a schema with the default stop words, and nests at most 24 operators; their expected text is the recorded reference output, which the Python model must reproduce before the binaries are compared with it. Deeper recorded queries reach the stack limits and are left out.

The deterministic seed `0x0F7A11E5` gives 9,999 rows: 1,028 lexer rows, 8,780 parse rows over 4,001 generated queries in dialects 1, 2 and 3, with random spacing, commas and stray operators that produce syntax errors, and 191 reference rows. Every row kind and column is mutated as a negative control, together with empty, truncated and extra output and six semantic mutants, each produced by a variant of the Python model: no dialect 2 right merge, no dialect 1 term groups, patterns binding like terms in dialect 2, a kept double negation, stop words kept as terms and the end token placed at the query length. All 14 controls must be rejected. [source-sha256.json](source-sha256.json) pins the eight modelled `src/ftquery` sources and the three test-data files the corpus reads; a change stops verification for review and reconciliation. Hashes detect drift; they do not establish refinement.

The receipt records the named theorem manifest with each theorem's axioms, the kernel inventory, per-area theorem names and comparison counts, source, trace, result and executable hashes and the compiler versions. The areas are `lexer`, `parser` and `reference`, and each has comparison rows. All 54 named theorems and all 231 kernel-checked theorems depend only on `propext`, `Classical.choice` and `Quot.sound`; there is no `sorry`, no project axiom and no native evaluation. Field modifiers, tags, numeric and geo filters, phrases, fuzzy terms, parameters, vector clauses, attributes, the stem expansion, stack limits and the rest of the dialect 2 grammar are outside this fragment. No performance claim is made here.
