# Vector package contracts

This optional Lean 4.35.0 project covers invariants of the three vector packages that tests cannot exhaust: the Hadamard projection, int8 quantisation and binary encoding with their scores and the free list of the vector arena in `src/vmath`, the candidate heaps, the visited set, the graph links, the link encoding and the twin chains of `src/hnsw`, and the compiled filter programs of `src/vfilter`, and, for the labelled vector set of `src/vsettype`, the exact merge of partition results, name resolution and the reader's view, the independence of each label's partition from data the reader cannot see, the agreement of the labels-off and labelled paths on a plain set and the move of an element between labels, the owner scopes of the vector set (who sees what across owners, resolution with the own-before-shared tie, the exact merge over own and shared partitions, isolation between owners and forgetting an owner, the owners-off and single-owner agreement with the labels model, and the accounting of compact owner blocks), and, through a copy of the server built without `main.odin`, the labelled vector set commands as `access_enter`, `label_step` and the `cmd_vset` handlers run them. It uses only Lean core/Std, adds no server dependency and makes no claim that the Odin executable is formally verified. The theorems are about Lean definitions that transcribe the Odin procedures as written; the bridge supplies finite evidence that the actual packages agree with those definitions.

Run from the repository root:

```sh
python3 -I proofs/vector/verify.py --lean-bin /absolute/path/to/lean/bin --odin /absolute/path/to/odin --output /absolute/path/to/results
```

`LEAN_BIN_DIR` supplies the Lean directory when `--lean-bin` is omitted, and the Odin compiler is taken from `--odin`, then `ODIN`, then `PATH`, then `~/odin/current/odin`, the same order `build.sh` uses. The default output directory is `proofs/vector/.build`. The verifier removes a previous success receipt, checks the source drift gate, builds the Lean library and `vector_model` executable and the Odin harness with `-vet -strict-style` under the repository's `.build/proofs/compiler.lock`, runs the shared [kernel audit](../README.md#audit-coverage) with `Vectors.lean` as the printed manifest, generates the deterministic corpus, runs both executables on it and compares every row with independent Python expectations and with each other. It uses nice 10, one allowed CPU, one Lean thread and two Odin compiler threads, and starts no server. A full run takes about thirty seconds after the first build. The [aggregate runner](../README.md#run-the-proof-projects) runs this project too, as `--project vector`.

`Vectors/Projection.lean` defines the sign of row `j`, column `i` exactly as `hadamard_entry` does, negative when the 64-bit population count of `j AND i` is odd. The product of two entries in one column is the entry of row `j XOR k`, so the inner product of rows `j` and `k` over `n` columns is the Walsh sum of `c = j XOR k`. For `c = 0` it is `n`. For `c ≠ 0` with lowest set bit `s` and `r = n mod 2^(s+1)`, `walsh_closed` gives the exact value `sign(c, n - r) * min(r, 2^(s+1) - r)`: whole blocks of `2^(s+1)` columns cancel and only the last partial block remains. Every power of two `n` therefore has pairwise orthogonal rows (`rows_orthogonal_pow2`). For every shape the code accepts (`1 ≤ input ≤ 2^19`, `1 ≤ output ≤ input`), `projection_rows_orthogonal_iff` states exactly what holds: the first `output` rows are pairwise orthogonal if and only if `output ≤ 2^twoVal(input)`, the largest power of two dividing `input`. Non-power-of-two inputs are accepted and their rows are generally not orthogonal: rows 0 and 1 of `input = 3` have integer inner product 1, which is 1/3 after scaling, and with `input = 768`, `output = 257` rows 0 and 256 have inner product 256, again 1/3 after scaling (`rows_counterexample`, `rows_counterexample_768`). At most `2^s` in absolute value survives for a pair whose XOR has lowest bit `s`. The package test checks orthogonality only for `input = 64`; no caller outside `vmath` constructs a Hadamard projection yet.

`Vectors/Quantise.lean` models `q8_round` on finite values as rounding half away from zero after clamping to [-127, 127]; Odin's `math.round` is Go's exact bit-manipulation rounding, so this matches it on every finite float. `quantise_error` proves that for `range > 0` and `|x| ≤ range` the reconstruction `q * range / 127` is within `range / 254` of `x`, and `quantise_reconstructs` and `dequantise_error` lift this to the whole `encode_scaled` and `decode` path, including the all-zero case and the `norm` factor (`range * norm / 254` for the original component). These rational theorems are unaffected by the change that makes `q8_round` map both infinities to 0, because no finite input reaches that branch (`q8RoundX_finite`). The new branch is stated at the float level, where it is true: `XF` adds the two infinities and NaN, `mulX` multiplies them with the IEEE special-value and sign rules, and `q8RoundX` sends every non-finite value to 0 and stays within [-127, 127] (`q8RoundX_bounds`, `q8RoundX_special`); before the change an infinity rounded to ±127 (`inf_round_counterexample`). An infinite product arises only when `127 / range` itself overflows f32, which `scaleX` decides at the exact rounding threshold `2^128 - 2^103`. When it does not, `quantiseF` equals the rational quantiser (`quantiseF_finite`); when it does, every code is 0 (`quantiseF_overflow`). `tiny_range_overflows` shows that every range below `2^-126`, and so every input made only of f32 subnormals, overflows; normal ranges up to about `3.7e-37` overflow too. For such inputs the reconstruction is 0 and the error bound weakens from `range / 254` to `range` (`overflow_reconstruction`); `overflow_bound_counterexample` shows the rational bound is false at the float level for the input `2^-140`. In the encode path a vector whose squares all vanish stores norm 1 by the zero-norm rule, so a subnormal-only input stores all-zero codes, norm 1 and range `max|x|`, as the reference does. `Vectors/Binary.lean` proves that the binary encoding sets bit `i % 64` of word `i / 64` exactly when component `i` is positive, keeps every word below 2^64 and leaves every padding bit clear. `binPaddingClear_iff` proves that `bin_padding_clear`, which inspects only the last word, accepts exactly the words whose bits at positions `dim` and above are clear. Under that condition `hamming_le` bounds the Hamming distance by `dim`, so `score_bin = 1 - h/dim` lies in [0, 1]; `encoded_score_unit` closes the loop for two encoded vectors. The bound needs the padding condition: one dirty word gives `h = 64` for `dim = 1`, a score of -63 (`hamming_counterexample`). The code establishes the condition by zeroing words before encoding and by checking it when vectors are loaded. `score_antitone` and `score_unit` cover the mapping `1 - d/2`, and `q8Dist_range` shows the clamped int8 distance stays in [0, 2]. The float `distance_from_dot` path has no clamp; its rounding is covered by the package tests, not here.

`Vectors/Arena.lean` models the norm array of a vector arena as u32 words, with a free slot's word `0x80000000 | next` and `0x7FFFFFFF` ending the list, so the last free word reads `0xFFFFFFFF`. `ArenaInv` names the free list explicitly: it is duplicate free, lies below `high`, starts at `free`, links each entry to the next with `free_entry`, ends at the terminator, accounts for `live = high - length`, and every slot outside it holds a word with bit 31 clear. `freeEntry_spec` shows every free word has bit 31 set and decodes back to its successor, because `SLOT_LIMIT = 2^31 - 1` keeps every slot below the terminator code. `liveNorm_clear` shows that `live_norm` accepts exactly the words with bit 31 clear and the NaNs, clears the sign of a NaN and never returns a word with bit 31 set when it accepts, so `set_raw`, `set_normalised` and `insert_normalised` can never store a word that reads as free (`live_never_free`). `arena_set` stores `live_norm`'s value without checking it; `encoded_norm_clear` proves that is safe exactly when the encoded norm is non-negative or NaN, and `negative_zero_counterexample` shows that a stored `-0` would read as a free entry. The encode path meets the condition by IEEE arithmetic outside the proof: every square is `+0`, positive, `+inf` or NaN, sums of such values never produce `-0`, the square root keeps them non-negative, and a zero norm is replaced by 1. `arena_free_invalid` and `arena_free_already` prove that `arena_free` returns `Invalid_Slot` for slots at or above `high` and `Already_Free` for every slot on the free list without changing anything, `double_free_detected` shows the second free of a slot is always rejected, `arena_free_spec` and `arena_alloc_spec` show that freeing pushes the slot and allocation pops it or appends a fresh slot whose norm is 0, and `arena_live_iff` shows that `arena_is_live` is exactly membership below `high` outside the free list. `free_walk` proves that following `free_next` from the head visits exactly the free slots, each once, and reaches the terminator within `high + 1` steps, so the list is acyclic.

`Vectors/Heap.lean` transcribes the hole-based loops: push appends the candidate and moves parents down into the hole, pop moves the last element into the root hole and moves the closer (or farther) child up, with the code's `child + 1 < n` test and the `(distance, id)` tie-break of `closer`. The max heap is the same algorithm under `farther a b = closer b a`, which matches each comparison in `max_heap_push` and `max_heap_sift_down`. The proofs track a virtual array, the code array with the moving candidate written into the hole, which changes by one swap per step, so contents are preserved as a permutation. Push, pop and replace-top preserve the heap property. The candidate returned by top, pop and replace-top is not beaten by any element under `(distance, id)`, so it is the minimum of a min heap and the maximum of a max heap, and the remaining contents are the old contents without that candidate, plus the new candidate for replace-top.

`Vectors/Visited.lean` models one-byte stamps and epochs: growth to `max(n, cap + cap/2, 64)` with zeroed new stamps, the reset to all-zero stamps and epoch 0 when the epoch equals 255, and the increment modulo 256. The invariant is that every stamp is at most the epoch. It holds after `visited_init` and is preserved by begin and mark. After a begin no slot is contained, and within one search `visited_contains` is true exactly for the slots marked since the last begin, while each mark returns true exactly on the first visit (`search_visited`). At the wrap the stamps are all zero and the epoch is 1 (`begin_wrap`); otherwise a begin keeps the stamps (`begin_keeps`) and moves the epoch to `epoch mod 255 + 1` (`begin_epoch`). For any sequence of searches from `visited_init`, `rounds_epoch` gives the epoch after `k` searches as `(k - 1) mod 255 + 1`, `rounds_clear_every_255` shows that the begin of search `k + 1` clears the stamp array exactly when `k` is a positive multiple of 255, and `rounds_exact` proves exact membership in every search, including those whose begin wraps. The reset is necessary: without it the epoch wraps to 0 and an untouched slot with stamp 0 reads as visited (`naive_wrap_counterexample`). The invariant is also necessary: a stamp above the epoch, which the package test plants deliberately, makes an unmarked slot read as visited after one begin (`stale_stamp_counterexample`).

`Vectors/Graph.lean` models one layer as an adjacency list per node and a presence predicate. `Wf` bundles two-way links, no self links, no duplicates, every list within the layer capacity and lists that reference only present nodes. `list_remove` swaps the last element into the hole and is proved to be a permutation of `List.erase`; `list_replace` writes the first match. `connectStep` follows `connect` as written: append when the neighbour has room, otherwise evict `shrink_victim`'s choice, and afterwards call `adopt` when the victim has no link left or, for a victim other than the new node, when the island guard reports it stranded. `adopt` links the orphan to a neighbour of the hub with room that is linked to it in neither direction. `connect_wf` proves that `connect` preserves `Wf` for any eviction choice that returns a member of the full list or the new node, any island guard and any adoption choice that returns a candidate (`adopt_conn`), using a pending-link invariant for the selected nodes not yet processed; `closestPick_ok` shows the code's nearest-candidate choice qualifies, and `stranded` transcribes the bounded breadth-first search of at most 64 nodes, which no theorem needs beyond being a Boolean. `shrinkVictim_mem` proves `shrink_victim` makes such a choice for any distances, comparison and permuting sort. `shrinkVictim_spares` proves that either the victim keeps another link or every member of the full list and the new node has at most one link, and `evict_never_isolates` closes the remaining case: with a capacity of at least 2 the adoption always finds a partner, so after every eviction the victim has a link. `insertionSort_perm` and `insertionSort_sorted` cover the insertion sort `candidates_sort` uses for at most 48 elements, and `candidatesSort_perm` extends the permutation property to any permuting sort for longer arrays. `removeNode_wf` proves that removal from every neighbour list, freeing the slot and the repairs, including `link_pair` and relinking through `connect`, preserve `Wf` and that afterwards no list references the removed node. `insertNode_wf` covers insertion, and `insert_layer_wf` and `remove_layer_wf` instantiate the capacity with `M` on upper layers and `2M` on layer 0; `layer_cap_fits` shows `2M` fits the u16 degree counter for `M ≤ 32767`. Insert now searches every layer before linking any of them; `insert_search_first` proves that this order builds the same graph as searching and linking layer by layer, for any search that reads only its own layer and any linker that writes only its own layer.

`Vectors/Width.lean` models link storage as little-endian bytes. `link_width_fits` proves that every slot id below the capacity is below the terminator of the width `link_width` chooses, for capacities up to `SLOT_LIMIT`, so ids are representable and never equal the terminator; `link_width_mono` shows the width only grows with capacity. `word_set_get` and `word_set_other` prove that a stored word reads back modulo `256^w` and leaves every other word unchanged, `load_three_of_four` shows that the 3-byte load's 4-byte read masked to 24 bits is the 3-byte value, and `decode_encode` recovers a stored list. `reencode_preserves` proves that widening a row of ids to a larger width and decoding at the new width gives the same ids, `reencode_terminator` that the terminator maps to the new terminator, and `counts_fit` that upper-layer counts, at most `M ≤ 32767`, are never mistaken for the terminator. Re-encoding therefore leaves the abstract adjacency, the twin back pointers and the free-slot list unchanged, which the bridge also checks on the real index.

`Vectors/Twin.lean` models the whole index: the slot count, the levels byte of every slot, `twin_link` as `next`, word 0 of a twin's layer-0 row as `prev`, the adjacency of every layer, the free-slot stack and the counters, entry and maximum level. Slot kinds come from the levels byte (`twin_kinds`): Free 255, Reserved 254, Twin 253 and Node with level at most 30, and live means Node or Twin. Presence on layer `l` means a Node with level at least `l`, and `GraphWf` asks for `Wf` on every layer with `2M` on layer 0 and `M` above, so twins are present on no layer, appear in no list and have no links (`twin_absent`). `TwinInv` states the chain invariants: every byte is one of the four kinds, `next(x) ≠ NONE` only for live `x` and then names a Twin, `next(prev(t)) = t` for every Twin and `prev(next(x)) = x`, some rank strictly decreases along `prev` between twins, the free stack lists exactly the Free slots, `twins = #Twin`, `live = #Node + #Twin`, and the entry is a Node at `max_level`, at least as high as every node, whenever `live > 0`, and `NONE` otherwise. From it `twin_head_reached` proves that following `prev` from any Twin passes only twins and reaches a Node, its head, within `#Twin` steps, `twin_chain_ends` that following `next` from any slot reaches `NONE` within `#Twin + 1` steps, so chains are acyclic and end at `NONE`, `twin_heads_one` that each Node heads at most one chain, and `twin_free_next` that Free and Reserved slots have `next = NONE`. `attach_inv` proves that Attach, which makes a Reserved slot a Twin directly after a Node head, keeps both invariants and leaves the graph untouched; `remove_twin_inv` covers Detach, which unlinks a twin from both chain neighbours and frees it; `promote_inv` covers Promote, which gives the first twin the head's level, rows and upper block, replaces the head by the heir in every neighbour list on every layer with `list_replace`, moves the entry and frees the head. Promote keeps well-formedness because it is a relabelling: the heir was present on no layer and appeared in no list (`relabel_wf`, `replaceAll_spec`). `reserve_inv` and `release_inv` cover the free-slot stack. `insert_inv` proves that insert, as a first node, as a Twin when the coincident test names a head, or as a Node linked on every layer from the top down, keeps both invariants together for any per-layer selections that are duplicate free, exclude the new slot and name present nodes; `remove_inv` proves the same for removal of a twin, removal of a head with twins through Promote, and plain removal with unlinking, `pick_entry` and per-layer repairs that preserve `Wf`. `insert_keeps` and `remove_keeps` instantiate these with `shrink_victim` and with `repair` and any relink that satisfies `RelinkOk`. `coincidentHead` transcribes the twin test: the new node becomes a twin of `h` when the first `T = clamp(M/2, 1, 2)` layer-0 candidates tie exactly at `d0`, `d0 ≤ d(q,q)`, at least `T` candidates in the tied prefix satisfy `d0 ≤ d(c,c)`, and `h` is the first of them; `coincident_mem` shows `h` is one of the candidates, which are present nodes, and `coincident_tie` records the tie conditions.

The search is abstract in the theorems. Insert and relink hand `connect` a candidate list that is assumed duplicate free, without the node itself, and made of present nodes, and the repairs are any per-layer functions that preserve `Wf`. The code meets this because results come from entry points and stored links, the visited stamps admit each node once per search, `results_to_work` drops the base node and `select_neighbors` takes a sublist of the work list. Distances are an arbitrary function and comparisons arbitrary, so the graph theorems also hold for NaN distances, but the sort is assumed to return a permutation of its input. Scratch-list appends and the allocations for `twin_link`, slot capacity and the upper pool are assumed to succeed; an out-of-memory failure that left `shrink` empty would index outside it and is not covered. Graph connectivity, recall and search quality are not claimed. For the comparisons the oracle executes the code's search exactly, with `greedy_closest`, `search_layer` on the modelled heaps and visited set, `results_to_work`, `select_neighbors`, the island guard and the nearest adoption choice, and passes its results to the same `insertOp` and `removeOp` the theorems are about; it starts each search from a fresh visited set, which `search_visited` justifies.

`Vectors/Filter.lean` runs the postfix code as `program_execute` does, with an explicit fault outcome for the stack accesses that `#no_bounds_check` leaves unchecked. `emitDepth` repeats the depth accounting of `parser_emit`, and `parser_finish` accepts exactly the code with no broken step and final depth 1. `accepted_never_faults` proves that accepted code never underflows the stack or exceeds `program.depth`, so neither the inline stack of 64 nor the allocated one is overrun, and ends with exactly one value. Because the code has no jumps, reaching any `Load` of a missing field returns false (`missing_field_fails`), and `missing_field_evaluate` lifts this to `evaluate`; this is why `.a == 1 or .b == 2` fails an element without `b` even when `a` is 1. `execute_blob_free` shows programs without loads ignore the attribute blob, and `constant_agrees` shows the cached compile-time result equals run-time evaluation. One edge case remains: for depth above 64 the compile-time run allocates its stack, and if that allocation fails the cached result is false even though a later run would compute the expression, so `constant_agrees` assumes depth at most 64 or the same allocation outcome. A non-nil attribute is required; `evaluate` with a nil attribute returns false.

`Vectors/Merge.lean` models a search over a reader's view as the code runs it: each visible partition returns its own top COUNT (`topk`, a stable merge sort followed by take), the results are concatenated and sorted again and the first COUNT kept (`mergeTop`). `sorted_take_mem` characterises the prefix of a sorted duplicate-free list: an element is among the first `k` exactly when fewer than `k` elements are strictly before it. From this, `merge_exact` proves that the merge of the partitions' own top COUNT equals the top COUNT of their union for any total order that is antisymmetric on the elements, provided the union has no duplicates, which holds because a reader's view resolves every name to one copy. `merge_filter_exact` applies the FILTER predicate inside every partition, `merge_truth` covers TRUTH and the code's per-partition `min(COUNT, count)` (`topk_min_length`), and `merge_epsilon` places the EPSILON cut after the merge as the code does. `merge_relative` covers graph partitions: when exact partitions supply their exact top COUNT and every graph partition supplies its own result, any sorted duplicate-free subset of at most COUNT of its elements (`OwnResult`), the merged reply is the exact top COUNT of the union in which each graph partition contributes just its own result. A FILTER-EF budget therefore acts per partition, since nothing outside a partition reaches its own result. `hitLe` is the reply order of `named_better`: higher score first, NaN after every number, then element name in byte order. `hitLe_total_order` proves it total, transitive and antisymmetric, which gives `hit_merge_exact`.

`Vectors/Resolve.lean` transcribes `resolve` as a loop over a name's copies in creation order: the copy at the command's own label wins wherever it appears, otherwise the loop keeps the first visible copy of strictly higher rank. `resolve_visible` and `resolve_congr` prove that the result depends only on the visible copies, in their relative order, when the reader can see its own label. `resolve_own`, `resolve_none_iff`, `resolve_highest` and `resolve_older` give the specification: the own copy if present; otherwise the visible copy that no visible copy outranks, which strictly outranks every earlier visible copy, so among copies of equal rank the oldest wins. These hold for any strict weak order (`RankOrder`). `rankGt` is the lexicographic order on level, compartment count and trust and is proved to be one (`rankGt_order`, `rankGt_lex`); dominance with trust is reflexive and transitive. `own_outranked_only_by_trust` shows that a label the reader dominates can outrank the reader's own label only through higher trust, so without trust the own-label rule never changes an answer. `LState` is the set: a partition per label, the copy list per name and a stream per label. `viewOpen` builds the view object as `view_open` does, filtering the present labels by visibility, ordering them by `label_order_less` and computing the shadowed copies from every name with at least two copies. `restrict` removes everything the reader cannot see. `viewOpen_restrict`, `viewFind_restrict` and `viewRange_restrict` prove that the view object (visible partitions in order, shadowed copies, VCARD size and attributes count), the resolved copy of every name and every VRANGE answer are unchanged by that removal. Card, membership, attributes, sampling inputs, links over resolved copies and the VINFO sums are functions of the view object and the visible partitions. `skipShadows_spec` proves the position loop of `view_ref_at`: for strictly increasing shadowed positions it returns a position that is not shadowed and has exactly `t` unshadowed positions below it, so the sampler's index `t` maps to the `t`-th unshadowed element of the partition.

`Vectors/Partition.lean` models the writes as `apply_add_at`, `remove_at`, `set_attribute_at` and `remove_label` apply them. An exact copy at the command's label is updated or removed. A copy the writer can see at another label refuses the write. Otherwise a copy is created at the command's label, and a missing partition is created with a seed drawn from that label's stream. Draws by readers advance their own label's stream. Partition operations are parameters, so the proofs cover flat, graph and pinned partitions alike. `step_local` proves that a command at a label the reader cannot see leaves the reader's restricted state unchanged. `step_consistent` proves that a command at a visible label changes it as a function of the restricted state alone, because dominance is transitive. `run_purge` lifts both to histories: the reader's restricted state after any history equals its state after the history with every command at a hidden label removed. `partition_history` is the index-independence lemma that follows. A partition's state, including its level generator, and its label's stream are functions of the commands at labels that partition's label dominates. Commands at labels that partition's label does not dominate never affect it, and with them neither do hidden partitions, budgets or streams. `hidden_write_view`, `hidden_write_find`, `hidden_write_range` and `hidden_history_view` state the consequence for reads through a view. `modeAfterInsert` and `modeAfterRemove` transcribe `part_maybe_graduate` and `part_maybe_flatten`. `pinned_forever` proves that a pinned partition never changes mode, so a converted pre-scheme partition behaves exactly as before conversion. `hysteresis_gap` bounds how close a flatten can follow a graduation, and `convert_footprint` proves that the core and the converted block report the same footprint, so MEMORY USAGE does not change at conversion.

`Vectors/Plain.lean` compares the two paths on a set that was never converted, modelled as one partition at BOTTOM. `plain_write` proves that a labelled add, update, attribute change or removal at BOTTOM is the labels-off operation, given the set laws of the partition operations (`PartLaws`). `plain_viewOpen`, `plain_viewFind` and `plain_viewRange` prove that a reader who sees BOTTOM gets one partition and no shadows, the labels-off count and attributes, membership and the labels-off range. `plain_tie_orders_agree_on_scores` proves that the labels-off reply order (score, then insertion sequence) and the labelled one (score, then name) give the same sequence of scores for every COUNT, through `sorted_keys_eq` for any two total preorders that refine one order on scores. Equality of the elements themselves needs no tie at the COUNT cut.

`Vectors/Owner.lean` adds the owner dimension of `src/vsettype`. An owner is a natural number with `SHARED` 0 and `EVERY_OWNER` 2^32 − 1, the package's local stand-in for `src/owner`. `ownerLe` is the flat owner order the spec describes, a partial order with SHARED at the bottom, users incomparable and EVERY_OWNER at the top (`ownerLe_refl`, `ownerLe_trans`, `ownerLe_antisymm`, `shared_bottom`, `every_top`, `users_incomparable`); `accessValid` is `access_valid`, which refuses EVERY_OWNER and an owner without a stream and accepts SHARED with or without one (`access_every`, `access_shared`, `access_user`). A scope is a pair of a label and an owner, and `seesP` is `sees_part`: the reader at (r, o) sees data at (d, w) when r sees d and w is SHARED or o. For every valid owner this is dominance in the product of the label order and the owner order (`seesP_product`), and it is reflexive and transitive whenever the label visibility is (`seesP_sees`), so every generic theorem of the labelled model holds with scopes in place of labels. `gtP` ranks a copy by its label rank and puts an own copy above a shared copy of equal rank, and is a strict weak order whenever the label rank is (`gtP_order`). A user reader at (r, o) resolves in three steps, the rule the owner set on 9 November: its own copy at exactly (r, o), else the shared copy at exactly (r, SHARED), else the highest visible label rank among its own and the shared copies, an own copy before a shared one of equal rank and then the older copy within a scope. A SHARED reader's two exact copies coincide. `gtX` adds step 2 to the order: it puts the shared copy at the reader's own label above every other copy and is a strict weak order (`gtX_order`); the reader `readerP` resolves with it, while `rankReader` keeps the rank order of step 3. `resolveScoped` transcribes `resolve_scoped`: the exact own copy, then the exact shared copy, then two passes, over the owner's copies and then over the shared ones, each keeping the first visible copy of strictly higher label rank. `resolveScoped_eq` proves that it equals the generic resolution with `readerP` over any interleaving of the two lists and of other owners' copies, so the result never depends on how copies of different scopes were created relative to each other, which is why no copies registry has to link two scopes. `resolve_shared_exact` states step 2 and `resolve_falls_to_rank` that without either exact copy the reader resolves by rank; under that condition `resolve_rank_max`, `resolve_own_tie` and `resolve_scope_older` give step 3: the highest visible label rank wins, an own copy beats a shared copy of that rank, and among copies of one scope at one rank the oldest wins. `resolve_owner_result` shows the result is the reader's own or a shared copy it sees, and `resolve_other_owners` that another owner's copies never influence it. `refusalScoped` transcribes `visible_other_scoped` as `refuse_visible` calls it, the shared copy at the writer's label first, and `refusal_eq`, `refusal_iff` and `inuse_names_resolved` prove that a write is refused exactly when the writer sees another copy of the name, and that INUSE then names the copy a read at the writer's scope resolves to. `owner_viewOpen_restrict`, `owner_viewFind_restrict` and `owner_viewRange_restrict` are the restriction theorems for `seesP`, and `one_label_own_then_shared` shows that with one label an owner reads its own copy and otherwise the shared one. `no_own_resolves_shared`, `no_own_find_shared`, `no_own_view_shared` and `no_own_range_shared` prove that a user with no copies of its own resolves every name, sees the whole view object and gets every range exactly as a SHARED reader at the same label.

`Vectors/OwnerMerge.lean` closes the step that the merge theorems took as a hypothesis. `IndexInv` says the copy list of every name holds exactly the scopes whose partition holds the name, with no repeats, and every partition holds each name once; `indexInv_step` and `indexInv_run` prove that every command keeps it for any partition operations that satisfy `NameLaws`. Under it, `unshadowed_unique` and `view_names_unique` prove that the names left unshadowed across the reader's visible partitions are pairwise distinct: whenever a name is visible in two partitions, the copy the reader resolves to is in one of them and the other is shadowed. `Vectors/OwnerPartition.lean` instantiates the independence theorems at scopes. `owner_step_local` and `other_owner_step` prove that a write by another owner, at any label, or by anyone at a label the reader cannot see, leaves the reader's restricted state unchanged, `owner_step_consistent` and `owner_run_purge` give the history form, and `purge_keeps` lists what the purge keeps: the shared commands at labels the reader sees and the reader's own owner's commands at those labels. `run_filter_hidden` proves that removing any set of commands the reader cannot see leaves its restricted state unchanged, and `owner_isolation` with its view, find, range and stream corollaries states it for two distinct users: deleting every command of one user leaves the other user's replies at every label unchanged, and `shared_isolation` states that shared readers are unaffected by every owner. `owner_partition_history` shows that a scope's partition and stream depend only on the commands at scopes it sees, so one stream per scope is what keeps another owner's draws from shifting a visible draw. `forgetOwner` models `remove_owner`: `forget_gone` and `forget_keeps` show that it removes every partition and copy of that owner and nothing else, `forget_local` and `forget_history` that it is invisible to every other observer, the shared ones included, at any point of a history, and `forget_leaves_shared` that afterwards the owner's restricted partitions and copies are exactly those of a shared reader at the same label. `forget_find_shared`, `forget_view_shared` and `forget_range_shared` extend this to reads: after the forget, the owner resolves every name, sees the view object and gets every range exactly as a SHARED reader at the same label saw them before.

`Vectors/OwnerFootprint.lean` transcribes the ledger effects of `owner_graduate` and `owner_flatten`. Graduation allocates the full block on the owner ledger, carries the compact block's charge, charges the graph through the same charge and frees the compact block; a failed graduation releases the graph and the full block and leaves the compact block as it was (`graduate_fail_books`, `graduate_fail_unchanged`); flattening is the reverse. `graduate_books` and `flatten_books` prove that only the owner ledger changes, by exactly the change of the partition's footprint, and `graduate_footprint` and `flatten_footprint` give the new footprint. `Acct` holds the set's accounting as `shared_bytes`, `label_memory`, `scope_memory`, `owner_memory` and `owner_bytes` compute it, and `replace_isolates`, `graduate_isolates` and `flatten_isolates` prove that graduating or flattening a compact owner block changes only that owner's own accounting: shared bytes, every label's memory, the index tables, every other owner's memory and every other scope's memory stay the same, the owner's memory and the owner bytes move by the same amount, and `owner_bytes = Σ owner_memory` is preserved. `memory_identity` is the decomposition of `memory_usage`.

`Vectors/OwnerPlain.lean` proves the compatibility contract. `embedS` places a labels-model state at one owner and `embedC` a command; `embed_step` and `embed_run` prove that running the owner model on embedded commands is the embedding of the labels model's run, and `embed_resolve`, `embed_viewFind`, `embed_viewRange` and `embed_viewOpen` that resolution, the reader's view object, every resolved copy and every range are the embedded labels-model answers. `Vectors/Relabel.lean` models `relabel_at` as the code runs it: with a copy at the source label and none at the target, the element's raw bytes and attribute text are extracted, inserted into the target partition by `part_insert_raw` (created from the target label's stream when missing) and the source copy is then removed as `drop_ref` removes it. `relabel_as_remove_then_write` proves that the result is exactly a removal at the source followed by a raw insert at the target, `relabel_contents` that the target partition holds the extracted contents and `relabel_age` that the moved copy is the youngest copy of its name: the code appends it to the name's copy list, so the copy takes the age of a fresh write, not the age of the original. `relabel_is_write` proves that, when the raw insert agrees with an ordinary insert of the same value (`simMove_law` shows it does for the simulation) and no other copy is visible from the target, the move equals removing the source copy and then writing the element at the target. `Vectors/Commands.lean` lifts the package model to commands on one key. A key has copies in creation order, each at a label and pointing at another kind of value or at a vector-set object; an object is named by the label it was created at and its ordinal among the objects created there, so hidden creations do not renumber visible ones. `found` resolves the copy a command at a label uses, the own copy first and otherwise the highest-ranked visible copy, older on ties, which is `label_locate_other` after `db_find_in` misses the own partition. A write joins the object it found, creates one when nothing is visible, or is refused with WRONGTYPE or the in-use reply naming the found copy's label; a presence copy is added when the object gains a partition at the command's label and dropped when it loses it, as `vset_apply_change` does. Reads reply with any function of the reader's view (`kview`: the resolved copy, the object's dimension and the object restricted to the reader) and the reader's stream, and may advance that stream, which covers every read handler including VRANDMEMBER. The invariant `KInv` says every copy's label dominates its object's creation label; `kinv_step` proves every command preserves it, which fails once DECLASSIFY moves an element below the object's creation label, so the relabel commands are excluded. `reply_confined` (P1) proves that the reply to every command, write or read, is unchanged when the state is restricted to the command's label, `resolved_copy_visible` and `found_filter` (P7) that the resolved key copy and the view depend only on visible copies, and `kstep_local`, `kstep_consistent` and `unwinding` give `command_history` (P2, in the history form of `partition_history`): purging every command at a label the observer cannot see leaves the observer's replies unchanged. `single_level_plain` records that a scheme with at most one level, no compartments and at most one trust leaves labels off, so `cmd_vset` runs its labels-off branches, and `single_label_found` and `single_label_wreply` (P10) prove that with one label the key lookup is the plain lookup and no write reply is an in-use refusal.

The bridge [bridge.odin](bridge.odin) imports `src/vmath`, `src/hnsw`, `src/label` and `src/vsettype` directly and replays the same case file as [Main.lean](Main.lean). Projection rows compare every stored sign, check every magnitude against `hadamard_scale`, and compare the integer Gram matrix of the stored signs with the closed form. Quantisation rows run both `quantise_i8` and `encode_normalised(.Int8)` and `decode`, and print exact rationals of the f32 results. Inputs are dyadic with `range = 127 * 2^k`, so every f32 operation in those paths is exact and the comparison isolates the quantiser's logic from rounding; half-way components exercise the half-away rule, ranges of `127 * 2^-127` keep a finite scale of `2^127`, and ranges of `127 * 2^-128` and `127 * 2^-140` and subnormal-only vectors overflow it. Encode rows run `encode(.Int8)` on vectors whose squares vanish and compare norm 1, the range and the codes. Rounding rows cover every half-integer from -130.5 to 130.5, neighbours at distance 2^-16, `0.5 - 2^-25`, both infinities and NaN. Binary rows compare `encode_normalised(.Bin)` with `pack_bits` and the model, Hamming rows compare the active kernel table, the base kernels and `hamming_ref`, with exact scores for power-of-two dimensions, and raw-word rows include three dirty-padding pairs whose distance exceeds the dimension. Heap rows print the whole array after every operation, so the layout, not only the order of results, must match. Visited rows print the epoch, capacity and every contained slot after each operation, across wraps reached by moving the epoch to within three of 255 and across natural wraps after 255 consecutive searches. Sort rows run `candidates_sort` on arrays of up to 80 candidates, so both the insertion sort and `slice.sort_by` are compared. Width rows check `link_width` and `width_none` at every boundary. Arena rows run `arena_alloc`, `arena_free`, `arena_set_raw`, `arena_set_normalised`, `arena_insert_normalised`, `arena_set` and `arena_is_live` on a one-dimensional f32 arena and print every norm word and the free list walked with `free_next` after each operation, including double frees, invalid slots, negative and NaN norms; `live_norm` rows cover special and random words. Index rows run the real `reserve`, `insert`, `remove`, `release`, `reencode` and `search` on two-dimensional integer points with squared distances, and print every slot's levels byte, `twin_link`, twin back pointer and lists on every layer, the free-slot list, the counters, the entry and the width; the bridge fixes each insert's level by setting the generator state and the level scale, so the case file chooses levels. Repeated points produce twin attaches, twin removals and promotions, a low `ef_construction` with spread-out points produces evictions, adoptions and island adoptions, and removals exercise repairs and relinks. Filter rows are not compared; those results are proof-only.

The labelled rows (prefix `Z`) drive the real `src/vsettype` through `create_at`, `create_for`, `add_at`, `remove_at`, `set_attribute_at`, `remove_label`, `view_open`, `view_info`, `view_find`, `view_range`, `view_search`, `view_random_member`, `view_random_distinct`, `view_random_repeats` and `view_links`. Vectors are 64-dimensional binary sets, so every score is the exact dyadic `(64 - hamming) / 64` and is printed as an integer. Writes print the `Change` fields and the failure with the refused copy's label. Views print the size, the attributes count, the summed insertion counters and every visible partition with its label, mode, count and counter. Searches print names and scores, samples the drawn names, and links the names and scores of a flat partition's neighbours. Flat-to-graph thresholds as low as 3 make graph partitions common. A graph search is compared only where the Python generator has checked that the partition's own result is exact: EF 1,000 on partitions of at most a few dozen elements, a large FILTER-EF, no twin vectors inside a label and no tie at the COUNT cut. Otherwise the search runs with TRUTH. Graph-dependent outputs (max-level, graph links) are not printed. The Python model in [labelled.py](labelled.py) is written independently from the Odin code. While generating, it checks the P2 and P10 instances itself: every reader digest before and after a burst of writes at labels the reader cannot see is identical, every BOTTOM digest across a converting write is identical, and the labelled search on a plain set has the labels-off sequence of scores.
