This optional Lean 4.35.0 project covers request parsing and selected listpack encodings. It has no server runtime dependency, external Lean package, mathlib requirement, or performance claim. The kernel checks properties of executable models; bounded comparisons exercise the actual imported Odin packages against those models and a separate Python integer/byte oracle. Agreement on that corpus is tested implementation evidence, not a proof of the Odin program or compiler.

Run from the repository root with the official pinned toolchain already installed:

```sh
python3 -I proofs/encoding/verify.py --lean-bin /absolute/path/to/lean-4.35.0-linux/bin --output /absolute/path/to/results
```

`LEAN_BIN_DIR` supplies the same toolchain directory when `--lean-bin` is omitted. The verifier rebuilds the Lean executable and the bridge, checks the named contract manifest and every project-origin kernel declaration against the allowlist `propext`, `Classical.choice`, `Quot.sound`, checks source hashes and package file inventories, and rejects empty, truncated, extra, and corrupted output. A stale success receipt is removed before any gate. The receipt records versions, compiler/executable/source hashes, corpus/results hashes, nonempty coverage, and theorem dependencies. Compiler and bridge processes share the repository build lock, one allowed CPU, niceness 10, one Lean thread, and two Odin compiler threads. No server is started.

The parser model reads bytes operationally. It scans headers, parses canonical signed decimal i64 values, checks array/bulk limits, computes payload endpoints, and extracts binary arguments; its definition does not use serialization followed by deserialization. The arithmetic model uses unbounded integers to prove that the production ordered subtraction guard accepts exactly the nonnegative sums fitting a signed 64-bit `int`, and that the fast-path guard agrees with the slow-path helper. Successful operational `parseBulks` and `parseArray` results consume at most the input length. Every returned argument has its declared length, is an exact source slice, and has two terminator byte positions within the consumed prefix. These are index/length model facts, not an arbitrary-pointer safety theorem.

`Incremental` retains all received bytes and reparses after each fragment. Theorems show that feeding concatenated chunks has the same final result for every partition, including error and incomplete outcomes. This proves buffered reassembly and parser semantics for that model; it does not prove the connection adapter's saved-prefix allocation, ownership, mutation, scheduling, or optimized waiting logic. The actual bridge calls warmed `parse_array` and direct `parse_array_slow` on every generated prefix and checks all result fields and successful argument bytes. Whole-parser fast/slow equivalence is tested, while their bulk-end arithmetic equivalence is proved.

The chosen parser domain is RESP bulk arrays with machine-sized input, a representable base offset, canonical i64 decimal headers, a maximum array count of 2147483647, configured bulk maximum, and authentication limits. Tests include the default 512 MiB bulk limit, unauthenticated array limit 10 and bulk limit 16384, boundaries around both limits, and overflow cases without allocating the claimed payload. Zero and negative array counts, including `*-1`, yield an empty command; negative bulk lengths, including `$-1`, are errors. Overflow and malformed decimal headers remain distinct from incomplete input. Current source scanning accepts any byte following header CR and skips two arbitrary payload terminator bytes; the model and corpus preserve that behavior, alongside canonical CRLF cases. Inline syntax, alternate protocols, adapter ownership, allocation failure, huge-buffer pointer validity, and header cursor overflow at actual maximum allocation size are outside the proof claim. The source drift gate includes the adapter and configuration/ACL constants, but those files are not directly executed by this bridge.

The listpack model implements all six selected integer body classes: unsigned 7-bit, signed 13-bit, and signed 16/24/32/64-bit tagged little-endian integers. The complete tagged theorem proves `decodeBody (encodeInteger value)` returns the original value and selected encoded size for every mathematical i64. A generic base-256 digit reconstruction lemma and signed bit-vector refinement support the width families. The string theorem proves full body decode/encode preservation and encoded size across the 6-bit, 12-bit, and 32-bit length headers for arbitrary payload lists with length less than 2^32. Separate payload reconstruction and header/length theorems expose the boundary obligations.

Back-length proofs cover all lengths from zero through 2^32−1, the source's exact width transitions, byte-group reconstruction, and bounded terminating reverse decode. The transitions use one byte through 127, two below 16383, three below 2097151, four below 268435455, and five otherwise; some transition values intentionally acquire a leading zero group. Accepted modeled entry extents strictly advance and stay within the supplied limit and input. These results cover selected codecs and local entry bounds. A full deep-validation-implies-bounded-complete-traversal theorem, complete listpack mutation/refinement, packed containers beyond listpack, RDB, LZF, and other file formats remain outside this delivery. Validation and forward/reverse traversal are tested on bounded actual listpacks; traversal is invoked only after successful deep validation.

The deterministic seed is `0xE5A1C04`. The corpus has 13923 trace rows: 1629 overflow-guard cases, 8632 integer encodings including every signed 13-bit value, 152 string encodings, 330 back-length encodings, 1284 reverse-decoder cases, 642 body-decoder cases, 336 listpack integrity/traversal cases, and 918 parser traces containing 4042 prefix results. Small parser inputs are split at every boundary and truncated at every prefix; 300 seeded binary traces add irregular fragmentation. Integer sign extrema and size transitions, string lengths 63/64, 127/128 and 4095/4096, all five back-length width transitions, invalid tags, truncated bodies, corrupt headers/back-lengths/counts, and empty packs are exercised. Largest materialized payloads remain bounded; no giant declared length is allocated. Failed reverse decodes compare normalized failure results, rather than unspecified rejected-value outputs.

Receipt `area_evidence` counts one guard or parser-prefix comparison for area 4, and one integer/string/back-length/reverse-decoder/body-decoder/listpack row for area 5. Calling both actual parser paths does not double those counts. Source hashes detect drift; they do not establish semantic equivalence or extend the proof boundary.
