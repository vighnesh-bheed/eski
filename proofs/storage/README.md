# Storage contracts

This optional Lean 4.35.0 project covers selected contracts from phase-one area 1, main-keyspace table migration, and area 6, requested-byte pool accounting. It uses only Lean core/Std. It adds no server dependency and makes no claim that the Odin executable is formally verified.

Run from the repository root with an official Lean 4.35.0 toolchain:

```sh
python3 proofs/storage/verify.py --lean-bin /absolute/path/to/lean/bin --output /absolute/path/to/results
```

`LEAN_BIN_DIR` supplies the toolchain directory when `--lean-bin` is omitted. The default output directory is `proofs/storage/.build`. The verifier builds the Lean model and a focused actual-Odin bridge, checks the named contract manifest and every project-origin kernel declaration against the allowlist `propext`, `Classical.choice`, `Quot.sound`, and compares both executables against independently computed Python expectations. It clears a previous success receipt before checking source hashes or building. Builds share the repository's `.build/proofs/compiler.lock`, run at nice 10 on one allowed CPU, use one Lean thread and two Odin compiler threads, and start no workers or server.

`Storage/Table.lean` is an executable scalar model. It enumerates groups with the actual triangular step recurrence and 16 slots in increasing order, selects free controls, checks key and hash-tag before stopping at an empty group, copies full abstract entries to the destination, and tombstones selected source slots. Its logical specification separately counts entries satisfying an arbitrary predicate across both banks. Choosing exact-entry or key predicates expresses metadata preservation and unique-key preservation; this specification is not defined as the migration result. `CounterConsistent` connects the source's live counter to its live slots. The final-swap theorem requires that consistency and an actually zero live source after the selected batch.

The lookup proofs cover a finite group path with an explicit reachability invariant: earlier groups contain no empty controls and the target group contains a matching live slot. They prove lookup succeeds along such a path, returned slots match, first-free selection leaves prior groups clear when the selected index did not occur in their prefix, insertion creates a reachable key and preserves existing reachable keys, and live-to-tombstone replacement preserves all other reachable keys. Thus collisions and deleted controls have formal content in the scalar model. Valid power-of-two capacities of at least 16, a stable consistent key-to-hash function, valid source/destination storage, a nonduplicated probe prefix, positive work budget and sufficient reachable destination space are explicit preconditions. The theorem proving one move's progress assumes claim found a free slot. The triangular sequence's complete permutation property, bitmask/modulo correspondence, whole cursor-loop termination/composition for arbitrary budgets, and every insertion/erase invariant of the actual server are not proved. Group budget behavior and whole-loop grow/shrink/swap are also compared against actual Odin.

Key/value handles are abstract identifiers in the proofs. The bridge uses seven-byte inline keys, full 64-bit value-handle bits and the actual 48-bit expiry/16-bit clock layout. It checks byte/metadata copying; it does not dereference those synthetic values as objects. Heap/slab-key validity, object interpretation, key allocation/release, SIMD refinement, pointer safety, virtual-memory success, prefetch behavior, compiler correctness and the full `db_upsert_in` effects remain outside the proof. The harness performs low-level insertion/update between real migration batches and uses the actual `table_find_slot`/`table_place` path. Datatype-specific hash/set/sorted-set/stream tables are separate algorithms and are outside this project.

`Storage/Ledger.lean` models the requested-byte pool ledger as an operational `used` counter plus independently maintained owned tokens. `Valid` asserts equality with the outstanding-token sum, nonnegative charges, unique token IDs and a signed 64-bit budget. Reserve updates the counter and adds a fresh token; release searches/removes a token and subtracts its charge. Acquire validates positive payload and the 32-byte header bound, reserves, then explicitly releases the reservation if the modeled heap attempt fails. The inverse theorem proves that rollback restores the original ledger. Successful admission is proved safe under nonnegative existing balances and budgets at most `2^63-1`; zero-byte external reservations succeed within budget and preserve the numeric balance. Requested bytes include the allocation header and are not RSS, libc usable-size, mapped pages or OS memory pressure.

Fresh IDs and one consumption per token are ghost ownership obligations on callers. The actual external reserve/release API does not track IDs or reject double release; raw release requires the caller to own exactly that outstanding charge. The formal model's missing-token rejection is an ownership guard, not a runtime guarantee. Wrong-pool and wrong-length free tests use still-live allocations that the real `free` API safely rejects; no raw double free or unowned positive external release is attempted. Actual heap-allocation failure is not fault-injected; its arithmetic rollback is modeled/proved, while a real compound record/seed admission failure exercises production rollback. The allocator wrapper's resize/copy semantics and snapshot/object charge estimation or alias correctness are not proved by this project; their source fingerprints require review after drift. Worker concurrency, CAS linearizability, mutable limits during allocation, reference-count races and all scheduling/lifecycle properties remain separate work.

The deterministic corpus contains 9,080 table-operation comparisons and 1,539 accounting-operation comparisons, counted as output rows in `area_evidence`. It covers 88 grows/shrinks including empty tables, 604 partial batches, 88 zero-budget batches, repeated migration, final swaps, updates/deletions between batches, wraparound from the last home group, 40 keys with the same home group and low-seven-bit hash tag, 4,620 queries, 588 deletions, value/expiry/clock extrema, small and signed-64-bit admission boundaries, 24 safe rejected ownership/length checks and 12 real record-seed rollbacks. Python uses a separate key-to-entry dictionary, a closed-form triangular offset for placement and counters recomputed from occupied/deleted slots. It validates the physical inventory against the dictionary after every table operation. Its fixed-seed seven-byte hash oracle uses wide-integer arithmetic, and every insertion/query/deletion checks that the supplied hash equals the actual Odin hash. Finite agreement remains tested evidence, not a proof of Odin equivalence.

The bridge copies `src/table.odin` and `src/hash.odin` byte-for-byte into a private output overlay, copies the exact original value-type prefix, and appends exact `db_locate`, `db_rehash_groups` and `db_rehash_swap` procedure slices to the harness. Their source, slice and hash provenance is recorded. It directly imports the original keyspace package. The harness supplies a reduced database/slab context, fatal handler and immediate unmap callback; it uses no slab-backed keys, graveyard scheduling or expiry evaluation. A source drift gate covers every imported keyspace source plus mapped main-keyspace/accounting files. Hashes detect drift and identify artifacts; they do not establish refinement.

The receipt records the complete theorem/axiom manifest, per-area theorem names and comparison counts, source/model/trace/result hashes, exact compiler versions and tool/executable hashes, and overlay provenance. Controlled empty/truncated/extra output and every table/accounting output column mutant must be rejected. Missing tools, empty evidence, output noise, drift or failed comparisons produce no success receipt. No benchmark or performance claim is made.
