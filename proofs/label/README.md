# Access label contracts

This optional Lean 4.35.0 project covers the access-label leaf `src/label`: the label lattice, the marking syntax, the label table, its persistence encoding, the visibility bitsets, the accept adapters that admit search candidates, the read and write rules and the label-partitioned counters. It also transcribes the filtered search of `src/hnsw` far enough to state what the adapter guarantees about search results. It uses only Lean core and adds no server dependency. The theorems are about Lean definitions that transcribe the Odin procedures; the bridge supplies finite evidence that the actual package agrees with them, and makes no claim that the Odin executable is formally verified.

Run from the repository root:

```sh
python3 -I proofs/label/verify.py --lean-bin /absolute/path/to/lean/bin --odin /absolute/path/to/odin --output /absolute/path/to/results
```

`LEAN_BIN_DIR` supplies the Lean directory when `--lean-bin` is omitted, and the Odin compiler is taken from `--odin`, then `ODIN`, then `PATH`, then `~/odin/current/odin`. The default output directory is `proofs/label/.build`. The verifier removes a previous success receipt, checks the source drift gate, builds the Lean library and `label_model` executable and the Odin harness with `-vet -strict-style` under the repository's `.build/proofs/compiler.lock`, runs the shared [kernel audit](../README.md#audit-coverage) with `Labels.lean` as the printed manifest, generates the deterministic corpus, runs both executables on it and compares every row with independent Python expectations and with each other. It uses nice 10, one allowed CPU and one Lean thread, starts no server and takes about ten seconds after the first build. The [aggregate runner](../README.md#run-the-proof-projects) runs it as `--project label`.

The labels live in their own project rather than as an area of `proofs/vector` because `src/label` is a separate leaf with its own receipt, sources and corpus; keeping it apart leaves the vector receipt, its pins and its recorded counts untouched, and lets the vector, text and type layers depend on the label proofs without the label proofs depending on graph internals. The vector project has no model of `search_layer_filtered` to reuse, so the search transcription below is new.

`Labels/Lattice.lean` models a label as a level and a compartment bitmask, with `dom a b` exactly the Odin test: the level of `a` is at least that of `b` and `b`'s compartments are a subset of `a`'s. `dom_iff` restates the subset test bit by bit, and dominance is reflexive, antisymmetric and transitive. `dom_join_iff` and `dom_meet_iff` characterise join and meet as the least upper and greatest lower bounds, from which the bound, commutativity, associativity, idempotence and absorption laws follow; `meet_join_distrib` shows the lattice is distributive, and `bottom_least` makes the zero label the bottom. For a configuration of `L` levels and `C` compartments, `Valid` asks for a level below `L` and compartments below `2^C`; join and meet keep labels valid and `top_greatest` shows that the top label, the highest level with every compartment, dominates every valid label.

`Labels/Marking.lean` follows the parser byte by byte. `normalise` folds ASCII lower case to upper case, drops leading and trailing spaces and tabs and turns each interior run into one space, as the Odin loop does, and `normalise_canonical` proves it is the identity on canonical names: one to 64 bytes of `A`–`Z`, `0`–`9`, `-`, `_` and single interior spaces, every word starting with a letter or a digit. `addLevel_ok` and `addComp_ok` prove the configuration procedures keep every name canonical and every name distinct across levels and compartments within the limits of 256 each. `parse` rejects markings above 32,768 bytes and any byte other than a tab or printable ASCII, splits the level at the first slash, requires a double slash, splits the compartments at single slashes and rejects empty, unknown and duplicate names; `format` writes the level name and, when there are compartments, a double slash and the compartment names joined by single slashes in ascending compartment id order, which is configuration order. `parse_format` proves that parsing the format of any valid label under any well-formed configuration returns that label, which needs `splitAux_intercalate` for the token loop, `compsLoop_ok` for the duplicate check and `ofIds_idsOf` to rebuild the bitmask; `parse_valid` shows every accepted marking gives a valid label, `format_parse` that formatting any accepted marking gives its canonical form, which parses back to the same label, `format_injective` and `canonical_roundtrip` the canonical round trip, and `format_length` that every canonical marking fits the 32,768-byte limit.

`Labels/Intern.lean` models the table as the list of its labels in id order, starting from `[bottom]`. `find_iff` shows lookup by label is the inverse of lookup by id on a duplicate-free table, and `intern_ok` keeps the table duplicate free, with bottom at id 0 and at most 65,535 labels. `intern_prefix` and `intern_stable` prove the old table is always a prefix of the new one, so an id keeps its label for the table's lifetime, and `internAll_ids` extends this to any sequence: every id handed out names the same label in the final table. `ids_injective` proves distinct ids name distinct labels, `intern_id_lt` and `intern_id_ne_none` that every id fits in 16 bits and is never `0xFFFF`, `intern_full` that a new label at 65,535 entries returns `Table_Full` and leaves the table unchanged, and `intern_existing` that a known label is found even then.

`Labels/Codec.lean` models the persistence encoding: the magic `ESLT`, version 1, the level count and names, the compartment count and names, the label count and each label as its level, its compartment count and its ascending compartment ids, with little-endian 16-bit counts and one-byte name lengths. The decoder checks, in the Odin order, truncation, the magic, the version, the level count between 1 and 256, canonical and distinct names, the compartment count up to 256, a nonzero label count, each level, each compartment count and strictly ascending ids below the compartment count, bottom first, no duplicate label and no trailing byte. `decode_encode` proves that encoding a well-formed configuration and table and decoding the result gives them back, and `encode_decode` proves the converse for byte strings: every accepted input is exactly the encoding of what it decodes to, so the encoding is canonical and `decode_injective` follows.

`Labels/Visibility.lean` transcribes `visibility_refresh`: it extends the word array with zero words, then walks the new ids one 64-bit word at a time, collecting `dominance_bit` shifted to each id's bit position and OR-ing the chunk into its word, as the Odin loop does. `chunk_testBit` and `fill_testAt` give the bit of every id after one chunk and after the whole walk, `refresh_ok` proves the invariant `VisOk` (bit `i` is set exactly when `i` is below the table length and the reader dominates label `i`, no bit beyond the table is set, every word is below 2^64) survives any growth of the table by appended labels, and `refresh_eq_build` proves that refreshing after growth produces the same words as a fresh build. `visible_spec` gives the per-id check, `stale_closed` shows that ids at or above the built count are never visible, so a bitset that has not been refreshed fails closed, and `visible_after_growth` combines the two.

`Labels/Admission.lean` models the accept adapter: `gateAccept` reads the slot's label id from the per-slot array, fails closed past its end, and tests the visibility bit. `gate_exact` proves a slot is accepted exactly when its id is in the table and the reader dominates its label, and `gate_subject` lifts this to a subject whose visibility was built for `reader`, the meet of session and clearance, so the label is dominated by the clearance. `filter_exact` proves the combinator accepts exactly when the gate accepts and the filter passes, `filter_sound` names what passing means, and `filter_blind` and `filter_open` cover a program with no attribute source and no program.

`Labels/Search.lean` transcribes `search_layer_filtered` with its entry loop, the walk that stops when the closest candidate is farther than the worst of `ef` results, the unbudgeted branch that gathers and measures all unvisited neighbours, the budgeted branch with its early exits, and `twins_accept`, together with `push_result`, `results_take`, `search_filtered` and `brute_force`. `pushResult_mem` shows a push only adds its candidate, so `searchLayerFiltered_sound` and `searchFiltered_sound` prove that every returned result was accepted, for every graph, distance function, twin chain, entry point, `ef`, budget and bound. `search_dominated` instantiates the accept function with the gate built for a reader: every result's label is dominated by the reader; `search_filter_dominated` adds that the filter passes, and `search_within_clearance` that the label is dominated by the subject's clearance. These are soundness results only. `graph_search_interference` exhibits a four-node graph where moving one node whose label the reader cannot see changes which visible node the search returns, so approximate graph search over a shared index is not non-interfering, while `bruteForce_noninterference` proves an exact scan returns the same results whenever the visible slots and their distances are the same. In the code, `search_filtered` with a nil accept procedure runs the unfiltered search; the gate is never nil and the type layer must never pass nil.

`Labels/Rules.lean` models a subject as a clearance and a session label. Reads use the meet of the two, so `read_clearance` holds for every subject, and `read_iff` shows that for a well-formed subject, whose clearance dominates its session, reading means the session dominates the label. `write_iff` proves a write is allowed exactly when the clearance dominates the label and the label dominates the session, `default_write` that writing at the session is always allowed, and `flow_up` the Denning flow condition: any label the session can read is dominated by any label it can write. `modify_iff` proves that modifying or removing an existing element is allowed exactly at the session label, `modify_hidden` that an element the session cannot read is reported as not visible, and `lower_session_reads_less` that lowering the session never widens what can be read.

`Labels/Counters.lean` models the counters as a list of counts per label id with their total. `add_spec` and `sub_spec` prove the total stays the sum of the counts and below 2^64, with `add_overflow` refusing exactly the additions that would pass it, and `visibleTotal_le` and `visibleTotal_fits` show the visible total is bounded by the total, so the u64 arithmetic never wraps. `visibleTotal_spec` proves the bitset-based total equals the sum of the counts of the labels the reader dominates, `visibleTotal_noninterference` that it does not change when only counts of labels the reader cannot see change, `visibleTotal_mono` that a lower reader sees no more, and `visibleTotal_top` that a reader dominating every label sees the total.

The bridge [bridge.odin](bridge.odin) imports `src/label`, `src/hnsw` and `src/vfilter` directly and replays the same case file as [Main.lean](Main.lean); the independent Python model in [verify.py](verify.py) computes the expected rows with sets, dictionaries, `re`, `bytes.split` and `struct` instead of the transcribed algorithms. Lattice rows compare dominance both ways, join and meet of label pairs with compartments across all four words. Configuration rows add levels and compartments from raw bytes with case, tab and space variants, invalid bytes, overlong and duplicate names and both limits. Marking rows parse fuzzed, structured and mutated markings and print the label and canonical text or the error with its offset and length; format rows include invalid labels. Interning rows intern and look up labels with repeats. Persistence rows encode several configurations and tables, including one the encoder must refuse, and decode every prefix, every single-byte substitution of a small encoding with seven values, random mutations and crafted inputs, printing the error or the counts and the re-encoding. Visibility rows print the built count and every word after fresh builds and after refreshes that follow batches of 1 to 700 interned labels, including batches of 61 to 65 and of 127 to 129, over tables of up to 2,330 labels. Admission rows run the real gate and the filter gate with a compiled `.f == 1` program over per-slot attributes that pass, fail, lack the field or are missing, slots past the array, stale and `0xFFFF` ids, and the real `hnsw.brute_force` with the gate over indexes of up to 63 points with duplicate points. Rule rows set subjects with valid and invalid sessions and check reads, writes, modifications and the default write label. Counter rows add and subtract with underflow, overflow at the u64 ceiling and `0xFFFF`, and print the visible total and every count.

The deterministic seed `0x1A8E15` gives 38,358 rows: 1,505 lattice rows, 12,203 configuration, marking and format rows (10,925 markings, 2,989 accepted and every error kind present, including one overlong marking), 10,052 interning rows, 3,302 persistence rows (5 encodings and 3,297 decodes, 107 accepted and every decode error present), 251 visibility rows, 2,600 admission rows (2,200 gate rows over 70,802 slot decisions, 6,201 of them stale ids, and 400 brute-force searches, 387 with hidden slots), 5,600 rule rows and 2,845 counter rows (678 underflows, 2 overflows). Every row kind and column is mutated as a negative control, together with empty, truncated and extra output and seventeen semantic mutants: join computed as meet, dominance reversed, an unknown compartment accepted, compartments out of canonical order, a new label given an old id, trailing bytes and a duplicate label accepted by the decoder, an extra visibility bit, a gate reading past the label array, a filter accepting a slot the gate refused, a hidden slot returned by brute force, a write down allowed, a write above the clearance allowed, a read up, a hidden element reported as a write down, a visible total including a hidden count and a counter that wraps. All 67 mutants must be rejected. [source-sha256.json](source-sha256.json) pins the nine `src/label` sources and the modelled `hnsw` and `vfilter` sources; a change stops verification for review and reconciliation. Hashes detect drift; they do not establish refinement.

The receipt records the named theorem manifest with each theorem's axioms, the kernel inventory of every project-origin declaration, per-area theorem names and comparison counts, source, trace, result and executable hashes and the compiler versions. The areas are `lattice`, `marking`, `interning`, `persistence`, `visibility`, `admission` (the adapters and the search transcription), `rules` and `counters`, and each has comparison rows. All 136 named theorems and all 597 kernel-checked theorems depend only on `propext`, `Classical.choice` and `Quot.sound`; there is no `sorry`, no project axiom and no native evaluation. The hash index of the table, allocation failure, the actual graph search beyond the transcription (the bridge compares brute force only; graph search is checked by package tests), the attribute parser and filter semantics, concurrency and side channels other than the result sets stated above are outside the proofs. No performance claim is made here; the package benchmark reports the measured costs.
