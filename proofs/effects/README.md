# Rollback and expiry contracts

This optional Lean 4.35.0 project covers selected contracts from phase-one area 2, worker rollback, and area 3, expiry and AOF command translation, including hash-field expiry. It uses Lean core and Std. It adds no server dependency and does not establish formal correctness of the Odin executable or the whole persistence engine.

Run from the repository root:

```sh
python3 proofs/effects/verify.py --lean-bin /absolute/path/to/lean/bin --output /absolute/path/to/results
```

`LEAN_BIN_DIR` supplies the toolchain directory when `--lean-bin` is omitted. The official Lean version is pinned in [lean-toolchain](lean-toolchain). Python 3.11 or newer, the repository's Odin toolchain, and the repository's existing release Lua and diagnostics native build inputs are required. The verifier reads those native inputs without rebuilding them. It downloads no packages. The default output directory is `proofs/effects/.build`.

The verifier clears a previous success receipt before its gates, checks source fingerprints, builds both executables, and prints the named contract manifest in [Effects.lean](Effects.lean). The shared kernel inventory checks every project-origin declaration, including private, nested and unlisted declarations, and matches the named manifest to actual kernel theorems. Dependencies may include only `propext`, `Classical.choice`, and `Quot.sound`. Private negative fixtures containing a custom False axiom and an admitted theorem must compile and then fail this same dependency audit. The model modules contain no admissions or custom axioms. Builds share `.build/proofs/compiler.lock`, use nice 10, one allowed CPU, one Lean thread, and Odin `-thread-count:2`. The harness starts no server or worker threads and runs no performance benchmark.

[Effects/Rollback.lean](Effects/Rollback.lean) separates the captured snapshot list from mutable work records and from unpublished effects. The restoration loop writes captured records back into arbitrary work state; the specification independently selects the original record for affected identities and the work record elsewhere. The complete-state theorem requires that work touched only the authorized operand set. `restoreOwned`, which is called by `finish`, emits the candidate-destruction and snapshot-transfer events as it restores records. The once-only results count events from this control flow, including repeated operand identities. The executable model keeps the last occurrence when deduplicating, while Odin keeps the first; restoration and per-identity ownership properties are independent of this ordering. The models do not prove publication ordering.

`Record.value` represents logical string or object contents, rather than an Odin address. The modeled metadata is existence, clock, change flags, string-copy flag, key deadline, encoding, object kind, touched flag and hash minimum. A successful snapshot clone must preserve these logical contents, retained values must remain immutable, destructors must consume their owned resources successfully, and ownership tokens and charges must be live and distinct even when reference-counted values share a pointer. Those are explicit refinement assumptions. A rollback may install a different object address and allocation capacity, and its object charge reflects the snapshot clone's actual charge. There is no theorem that physical record bytes, pointer identities, allocator capacity or RSS return to their original state. Requested-byte accounting and its token obligations are described separately in [the storage contracts](../storage/README.md).

The rollback theorems start after successful capture of all relevant snapshots. Earlier snapshot or undo-capacity failures leave records untouched and need not set `rolled_back`; the real pre-capture case is tested. Candidate resources still owned by a kernel-local work object are cleaned by that kernel's discard path; the modeled restoration consumes the ownership bundle currently installed in each record. The actual fixtures check logical values, selected metadata, discarded effects, references and pool balance, rather than instrumenting every production destructor invocation. Cleanup traces and exact-once ownership are model proofs under the preceding assumptions, not a proof of allocator or reference-count implementation safety.

`Outcome.commandError` is separate from internal retry failure. Its theorem preserves arbitrary permitted work state and visible effects, including a mutation prefix when command semantics allow one. The real normal-error fixture invokes `cmd_set` with invalid PX 0 and checks its error reply, preserved value/deadline and zero dirty count. This fixture has no partial writes; preservation of a partially writing command error is modeled, not directly exercised here. No result claims that every error reply rolls back. Internal worker failures can request coordinator retry, whose command semantics are outside these rollback proofs.

[Effects/Persistence.lean](Effects/Persistence.lean) separates the operational hash update, explicit reply codes, command selection, and replay interpreter. Expiry replies are -2 for missing fields, 0 for a failed condition, 1 for an updated deadline, and 2 for immediate deletion. The reply-selection theorem requires consistency with the operation's actual result. Future deadlines cannot produce a consistent delete reply; due deadlines cannot produce a consistent update reply. HFE commands are represented per field. The actual translator can group accepted fields into one HPEXPIREAT; the Python adapter checks the RESP field count and expands that group before comparison. Mixed accepted/condition-failed/missing replies and duplicate fields are exercised in both packed and table encodings. Group construction and RESP formatting are tested, rather than kernel-proved. Malformed or absent reply fallback is excluded from the formal contract and corpus.

Field state is a physical map to value bytes and an optional absolute millisecond deadline. As in `set_ex_field`, expiry updates inspect `get_raw` without first removing an elapsed field: a permitted future update can revive a physically present expired field. The corpus exercises this behavior. These statements describe that lower-level operation and the worker path using it; other command paths that first purge expired fields require their own normalization step. HSET resets the deadline; HPERSIST changes only a still-live volatile field; deleting a field removes its deadline too. HINCRBYFLOAT is represented by its already-formatted final bytes and captured final deadline. The actual translator emits HSET and, when needed, HPEXPIREAT. The proofs establish this translation's value/deadline behavior; they do not prove floating-point arithmetic, IEEE 754 behavior or decimal formatting. Logical replay statements freeze time, suppress independent active expiry during replay, and use the same starting logical/physical field inventory. For native refinement, timestamps and arithmetic must fit the source's validated domain; hash-field command deadlines are at most `FIELD_DEADLINE_COMMAND_MAX`, and the corpus stays at or below 10^12 milliseconds. Parser validation and integer overflow are separate contracts.

An existing field remains readable at `deadline == now`: ordinary hash `get` and the live iterator use strict `deadline < now` expiry. Assigning a new expiry with `deadline <= now` deletes immediately. Persisting an existing deadline exactly at now succeeds. The active sweep can delete at `deadline == now`, while `expire_if_needed` does not enter its sweep at that exact minimum. The explicit boundary theorems and actual fixtures preserve these distinctions. Packed HPTTL returns -2 at that instant while table HPTTL returns 0; the harness records this existing behavior without changing it. `logicalLive` follows the read contract. Removing strictly expired physical fields preserves that view; active sweeping at equality is a separate operation. `RegisteredHash.cachedMinimum` does not define liveness: the real fixture also checks that persisting the last expiring field can leave a stale registered minimum.

[Effects/KeyTTL.lean](Effects/KeyTTL.lean) keeps ordinary-key expiry separate: a key deadline equal to now is expired. It proves selected relative and absolute SET translations, KEEPTTL, PEXPIREAT, PERSIST and DEL replay. Relative SET refinement has an explicit `validKeyDuration` premise requiring a positive duration and a mathematical absolute deadline at most `2^48 - 1`, which also fits i64. Implementation refinement additionally requires the captured deadline to equal that sum. The total model also defines the zero-duration boundary, which the real SET parser rejects. Ordinary-key fixtures call the actual AOF translators against explicitly seeded committed poststates and independently replay their output from corresponding prestates; they do not exercise the successful whole command paths. The normal-error fixture does invoke the real command handler.

[Main.lean](Main.lean), [bridge.odin](bridge.odin) and [verify.py](verify.py) share a typed trace protocol. Python computes expectations from a separate dictionary and direct integer comparisons, parses emitted RESP independently, and executes a separate replay interpreter. The Lean adapter materializes eight observable fields between trace steps to bound functional-map evaluation cost. This adapter is tested; its correspondence to the unbounded mathematical map is not itself a theorem. The deterministic seed is `0xE5A1EFFE`. The corpus has 7,958 hash operation rows: 1,958 boundary rows and 6,000 generated rows, with 552 resets. A grouped expiry request counts as one row. There are four rollback fixtures, one ordinary command-error fixture, ten ordinary-key translation fixtures and two exact-now fixtures. Receipt `area_evidence` counts five actual area-2 fixture comparisons and 7,970 actual area-3 comparisons; theorem names are listed separately for each area. Controlled bad physical state, command, live view, rollback flag, missing/extra row and bad axiom dependencies must be rejected.

The bridge builds a private output overlay by copying the original `src` tree byte-for-byte, omitting the application entrypoint and top-level test files, and adding only the harness entrypoint. The harness supplies its own version strings and pool setup without worker scheduling. It links the existing native archives through a build-input symlink. The receipt records copied source identity, native input hashes, compiler versions and hashes, executable hashes, traces, results and every theorem's printed dependencies. [source-sha256.json](source-sha256.json) gates the complete source tree, including existing tests. Added, removed or changed source stops verification. Fingerprints detect drift and identify artifacts; updating them does not prove refinement.

This project does not prove Odin-to-Lean translation, compiler correctness, pointer or memory safety, allocation/destructor behavior, concurrent ownership, scheduling, publication atomicity, full command or parser compatibility, all expiry policies, registry heap scheduling, RDB encoding, complete AOF rewrite/recovery, crash consistency, fsync, OS files or durability. Those limits remain even when all proof and comparison gates pass.
