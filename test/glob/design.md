# Test design

The suite has two independent sources of expectations. A deterministic Python generator creates raw byte pairs without consulting the matcher under test. A separately executed compatibility oracle supplies both case-sensitive and case-insensitive boolean results, preserved in a compressed data fixture. A Python state-set model checks a bounded subset of those results independently. Only the executable oracle's JSON interface is used; its source and binary internals are not inspected. The native harness compiles against the subject module but the test design does not read that module's implementation.

The generator uses a fixed PRNG seed and insertion-order deduplication. It covers every one-byte pattern against every one-byte text; empty pattern and text; short exhaustive combinations of literals, wildcards and escapes; targeted malformed classes; raw range endpoints spanning zero, ASCII punctuation and letters, 127, 128, 254 and 255; escaped values for every byte; randomized binary and syntax-heavy inputs; constructed matches and mutations; retries and late failures; and slices around common Linux page lengths. Expected false values are stored explicitly as zero bits rather than omitted. The runner accepts only actual JSON booleans from the compatibility oracle and compares exact boolean results in both modes.

Nonterminal-star chains have separate probes at 999, 1000, 1001 and 1002 stars. For example, pattern `("*a" repeated N times) + "Z"` and text `("a" repeated N times) + "Z"` match at N=1000 and reject at N=1001 in the compatibility fixture. Adjacent-star runs and terminal-star runs are separate cases, so collapsing adjacent stars is not confused with the nesting cutoff. Long failure probes use few stars to keep compatibility-oracle work finite; deeper chains use direct alignments.

The state-set oracle excludes every pattern containing an opening bracket and limits pattern length to twelve bytes and text length to eight bytes. It tokenizes literals, question marks, stars and backslash escapes. A trailing backslash is literal, as checked through the compatibility interface. It folds only ASCII uppercase letters when nocase is enabled. It also preserves the measured entry condition that initially empty text matches only an empty pattern, even when a nonempty pattern consists solely of stars.

For nonempty text, the state set contains token offsets reachable after each consumed byte. Epsilon closure advances past stars without consuming input. A star can consume a byte while remaining at its offset; a question mark or matching literal advances one offset. Acceptance requires the final token offset after all text is consumed. This is a finite automaton simulation with O(P*T) time and O(P) state space. It uses no regex or recursive backtracking, and it does not implement or assume bracket-class rules. The bounded pattern length keeps these checks far below the compatibility nesting cutoff.

The native harness allocates two independent anonymous mappings using Odin's Linux syscall APIs. Each mapping contains an inaccessible page, a readable/writable area rounded up to a whole number of pages, and another inaccessible page. Its page size comes from Python's current `mmap.PAGESIZE`. The area can hold the largest slice in the fixture. A left placement begins immediately after the first guard page, and a right placement ends immediately before the second guard page. Thus the left placement catches a read before the slice and the right placement catches a read after it. Empty slices point inside the left guard page or at the start of the right guard page, so dereferencing either empty slice faults.

For every case, the harness tests all four combinations of pattern-left/right and text-left/right, in both case modes. Input bytes are copied only into the accessible area and only for nonempty slices. The matcher receives only the guarded slices, never pointers into the ordinary fixture allocation. Any observed mismatch exits unsuccessfully with its case index and placement; an invalid read terminates the native process. Debug and release builds use the same fixture and guard placements.

The fixture layout is an eight-byte magic value `EGLOB001`, little-endian u32 page-size, case-count and maximum-slice-size fields, then records containing little-endian u32 pattern and text lengths, one flags byte, and the two raw byte sequences. Flag bits zero and one hold the case-sensitive and nocase expected results. The persistent page-size field is the canonical generation base; the runner replaces that field only in a temporary native copy with the actual host page size. Both Python and Odin validate fixture structure and dimensions. Gzip mtime is fixed to zero, and the manifest records compressed and raw SHA256 hashes.

A normal run requires only the production module, this test folder, Python and Odin. Regenerating expectations requires an explicitly supplied compatibility executable. The recorded functional checks establish agreement for this finite corpus and detect invalid accesses that reach the adjacent guards. They are not a proof over all possible byte slices and do not measure server behavior or performance.
