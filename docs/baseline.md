# Baseline measurement plan

`bench/baseline.py` defines every measurement that the later efficiency work starts from. Its `steps(context)` returns one step per measurement; the one-host run entry point, `tools/rented_run.py`, runs them after the correctness phase on the same host, one at a time, each as its own stage. A step starts and stops its own servers and containers, writes only under `<run>/<step>/`, and leaves nothing running when it passes, fails or is killed: every server and container it starts is registered with a watcher in its own session, which removes whatever is still registered when the step's process group dies. A step can be rerun alone. This page describes the plan as built; it holds no figures.

The plan has two profiles with the same steps. `full` is the measurement. `rehearsal` runs every step through the same code at toy sizes, so the whole plan finishes in about a quarter of an hour on a laptop; its results carry `"qualifying": false` and a note that their figures are not read.

## What every step writes

Each step's artifact is `<run>/<step>/result.json`, whose top-level `exit_code` is 0 only when the step passed, and everything else a step writes lies under `<run>/<step>/`. The run entry point is the only runner of the plan. `bench/baseline_run.py` is not a second one: it runs one step's driver, repeated as the step asks, and serves what the entry point does not, namely the repetitions, the per-repetition telemetry and memory records, the inventory of raw outputs and the cleanup watcher. Steps that wrap a driver this way keep, for every repetition, the driver's own JSON output, its log, the sha256 of every file it wrote, the memory every server reported just before it stopped (the engine's `INFO memory`, the resident and peak resident size of the server process from `/proc/<pid>/status`, and for containers the kernel `memory.peak` of their cgroup), and machine telemetry sampled every two seconds: package temperature, throttle events, the idle share of each server and client CPU and every process outside the run that used a tenth of a core on one of them. A host record at the start and the end of each step gives the kernel and its command line, the microcode, SMT and transparent huge page settings, the frequency policy of every role CPU, the load, memory, and the type and free space of the filesystem that holds the run.

## The contract with the run

This is the whole interface between `tools/rented_run.py` and `bench/baseline.py`; both sides test it.

The module defines three names. `AREAS` is the tuple of coverage areas in display order: `stock`, `memory`, `search-hash`, `search-json`, `full-text`, `vector-search`, `hybrid`, `aggregate`, `json`, `vector-sets`, `persistence`, `change-log`, `access`, `internal`, `simulation`, `trace`. `DOWNLOADS` is a tuple, empty when the plan downloads nothing, of dicts with exactly `name`, `url` (https), `sha256`, `path` (a file directly under `.build/downloads/` of the checkout) and `steps` (the tuple of step names that read it); `tools/host_setup.sh` fetches each one and checks its hash, and preflight reports each as cached, reachable or neither. `steps(context)` returns the steps in the order they run; it has no side effects, starts nothing and reads nothing outside the tree, and it must succeed in preflight, where `out` does not exist yet, the binaries have not been built and an image ID is empty when preflight could not resolve it.

The context always holds these keys:

| Key | Value |
| --- | --- |
| `profile` | `full` or `rehearsal`; the rehearsal runs the same steps at toy sizes |
| `out` | absolute path of the run directory |
| `binaries` | absolute paths for `eski` (the qualified release build), `eski-debug` (the same source and optimisation with debug information, for profiling only; it may be missing when its build failed), `eski-simulation` and `eski-change-log` |
| `server_cpus`, `client_cpus`, `control_cpus` | disjoint Linux CPU lists; the controller CPUs run the exam scheduler, its gates and telemetry and the noise floor's session controller. The operator passes `--control-cpus`; without it the run takes the highest permitted CPU in neither role, CPU 0 only when nothing else is left, and preflight stops when none exists |
| `ports` | `[first, last]`, forty consecutive free loopback ports; steps run one at a time, so each may use any of them |
| `images` | local image IDs for `redis`, `valkey`, `dragonfly`, `memtier` and `redis-search` |
| `limits` | `server_memory`, `client_memory` and `maxmemory` from `bench/testbed/design.json` |
| `python` | the interpreter's argv prefix |
| `seeds` | `first`, `count` and `steps` of the virtual seeds the correctness phase completed |

Every step is a dict with exactly `name` (lowercase letters, digits and hyphens, the same in both profiles, never a name of the run's own stages or files), `area` (one of `AREAS`), `command` (an argv list run with the checkout as working directory, standard input from `/dev/null`, output to `<name>.log` and its own session), `artifact` (a path under `<name>/`, relative to `out`, of the step's JSON report), `timeout` (seconds), `environment` (extra variables; the run removes the operator's `BENCH_*` and `ESKI_*` variables and sets `ODIN`, `PYTHONUTF8` and the smoke image variables), `needs` (the image keys the step uses) and `estimate_seconds` (computed from the configured sizes, never measured).

A step passes when it exits 0 and its artifact exists with a top-level `exit_code` of 0. A full-size stock step that finished its measurement with some cases not valid exits 1 and puts a top-level `measured` object in its artifact, with `excluded` and `valid` (both at least 1), `cases` (their sum) and `list` (the field of the artifact that lists every excluded case with its reasons). The run then records the step as measured, not failed, keeps it out of what a resume repeats, and lists it in `owed` as a rerun that is the operator's choice. On a timeout or a SIGTERM the run sends the step's process group SIGINT, then SIGTERM, then SIGKILL, 30 seconds apart; containers are outside that group, so every step removes its own. A step can be rerun alone: before a rerun the run moves the step's directory to `<name>.attempt-N` and its log to `<name>.attempt-N.log`, so the step always starts in a fresh directory. The two untimed probes of the correctness phase keep calling `bench/persist/aof_append.py` and `bench/search_json.py` with `--verify-only` and the same arguments as before.

## Method

The stock comparison uses the method of `bench/testbed/design.json` and the exam scheduler without the remote installation: `bench/stock_exam.py` builds a run root on the host with copies of the harness, the qualified binary, a profile that pins every image by its local ID and the plans of both phases, picks the design with four client threads when the host gives four client CPUs, takes the first server CPU as the one server core and the context's controller CPUs as the controller, and runs the idle watch, the calibration and the benchmark phase with every gate of the design. A gate that is not met holds the step instead of producing a number. Every timed run keeps the raw memtier output with its full histogram, the compressed histogram in its JSON and its per-second counts. A calibration case that is not valid stops the step before the benchmark phase. At the full profile the gates are never advisory: only the rehearsal profile passes `--advisory-gates` to the scheduler, and a test of the plan fails if a full-profile step carries it or anything but `--profile full`. A benchmark phase that finished with some cases not valid is recorded as measured with exclusions, as the contract above describes, so hours of measurement are kept and never rerun by a resume.

Eski runs natively while the competitors run in containers with a memory cap. Native is the primary measurement because the run qualifies one binary, built by the host's own compiler, and the image that `bench/image.sh` builds compiles the source again with the Dockerfile's pinned compiler, so it would measure another binary. Every engine gets the same server CPU, the same maxmemory and persistence off, and the clients and the network path are the same for all; the native Eski process has no container memory cap, which the measured workloads never approach. Memory is reported in the terms that apply to each: the container memory peak and the peak resident size of the server process for the competitors, the resident and peak resident size for Eski, and the engine's own `INFO memory` figure for all.

The search, JSON and vector set comparisons send the same seeded data and the same requests to Eski and to the pinned Redis 8.10.3 image. Before anything is timed, both engines are started side by side, loaded and indexed, and every distinct request of the plan is sent to both and its replies compared exactly. Each driver's `--verify-only` runs this check alone, at any size, and times nothing. A request shape whose replies differ is not timed, unless the difference is a named one that the output records and counts: the neighbours an approximate HNSW graph returns, which neither engine repeats between two fresh instances, where a reply still counts as unexpected unless it has the same total and number of results and every key both replies return carries the same distance or score; the order of documents with equal scores, where a reply that also differs in a score or in the keys of a complete group of equal scores still counts as unexpected; and JSON number arrays that the reference prints in half precision, where a reply that still differs after rounding both to half precision counts as unexpected. Three normalizations that remove what the engines never share are declared in the output: search projections are compared as field sets, FT.HYBRID's `execution_time` is removed, and cursor ids are removed. Each timed repetition then starts one engine fresh, loads the data, builds the indexes over the existing data and records the build time and the memory before and after, runs a warmup, and runs the planned requests over one connection and over several connections in separate client processes, recording every request's latency, its shape and whether its reply equalled that engine's verified reply. Requests that change data restore it within the request and touch keys owned by one connection, so their replies do not depend on interleaving. The engine order alternates by repetition.

`bench/persist/engine_compare.py` gives Eski, Redis and Valkey the same mixed dataset on a directory of the host disk, so fsync reaches the device, and checks the restored data against the saved data and across engines; its `--verify-only` makes one untimed pass per engine that reads every key back after the snapshot restart and every append-only write back after the log replay, compared with what was written and across the engines. `bench/persist/aof_append.py --verify-only` with a change log reader writes all of `--writes` and then finds every one of them, in order, in the change log mirror after the server has stopped. `bench/persist/save_load.py --verify-only` and `bench/vectorset/graph_load.py --verify-only` keep their own checks (the dataset digest after the restart; the restored and reloaded sets against the built one) and record no timing field. The noise floor step runs `bench/ab.py` with the qualified binary on both sides and writes the floor record that `bench/ab_report.py --floor` accepts, so later comparisons on the host know the smallest difference they can believe. The trace steps run each workload area against the debug-information build of the same source, started as a child of `perf record` with DWARF call graphs, or frame-pointer call graphs where DWARF is refused. A host without `perf` or without permission to use it fails these steps with that reason; a host that permits sampling but not call graphs records a flat profile and still fails the step, naming the refusal, so the call graphs stay owed. Preflight probes a call-graph recording and reports a refusal as a finding for the trace steps only; `sudo tools/host_setup.sh quiet` sets `kernel.perf_event_paranoid` to 1 and `kernel.kptr_restrict` to 0, which perf needs for call graphs and kernel symbols as an unprivileged user.

The specification step reads the pinned archive of the Redis benchmarks specification from `.build/downloads/`, where `tools/host_setup.sh user` (or `tools/host_setup.sh downloads`) put it after checking its sha256; when it is not cached the step downloads it from GitHub into its own directory, and when it is neither cached nor reachable the step fails with that reason. It then probes which commands Eski and Redis implement, and takes for every command group the case with the highest priority whose clients fit the client CPUs; groups without such a case are listed in the step's result. Its cases run through the same exam scheduler and gates as the stock comparison.

## Time and disk

The steps carry an estimate computed from their configured sizes, durations and repetitions and the planning constants in `bench/baseline.py`; the full plan adds up to about 10.5 hours, of which the stock comparison and the specification cases are about 7, plus about half an hour when the noise floor runs sequentially on a host with one server CPU. The full plan writes about 2.5 GB: about 0.7 GB of per-second machine samples and raw client output for the stock comparison, about 0.3 GB for the specification cases and their archive, about 1 GB of perf data for the seven trace steps, and less than 0.5 GB for everything else, including a copy of the debug build in each trace.

## Not covered

The module lists what the plan leaves out and why in `UNCOVERED`: an Eski container target, multicore scaling outside the compute thread step, search features Eski does not implement, FT.PROFILE, highlighting and summaries and DIALECT 4 paging whose replies differ by design, FT.HYBRID fusion, whose replies differed from the reference when the plan was built and which is therefore checked on every run and timed only once they are equal, a labelled-mode A/B against an older tree, and the tools that need a second binary, a workstation or network access rather than the host.
